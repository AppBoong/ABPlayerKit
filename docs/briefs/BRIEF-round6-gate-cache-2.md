# BRIEF: 라운드6 트랙 E 재게이트 (E-6 round 2) — 로직 변경 검증

당신은 트랙 E의 **재게이트**입니다. 1차 게이트(`REVIEW-round6-cache.md`)는 REQUEST-CHANGES였고, 구현자가 조치하는 과정에서 **지시 범위를 벗어난 프로덕션 로직 변경 2건**을 추가했습니다. 그 2건이 이번 재게이트의 핵심 대상입니다.

## 배경

1차 게이트는 부팅된 시뮬레이터가 없어 **정적 리뷰만** 수행했습니다. 구현자는 fix1 세션에서 처음으로 실제 테스트를 실행했고, **신규 테스트 33건 중 3건이 실패**하는 것을 발견해 근본 원인을 코드에서 고쳤습니다. 즉 1차 게이트가 APPROVE 방향으로 갔더라도 병합 후 CI에서 실패했을 사안입니다.

## 입력

1. `docs/briefs/RESULT-round6-cache-fix1.md` — 특히 **§2 (회귀 2건과 수정)**
2. `docs/briefs/REVIEW-round6-cache.md` — 1차 게이트(§9 지적 3건)
3. `docs/briefs/DESIGN-round6-cache.md` — 승인된 설계, 특히 §6 무회귀 가드 표
4. `git diff` — 작업 트리 전체

## 집중 검증 항목

1. **§2-1 `load()`의 재개-검증 게이팅**: "이 호출이 기존 prefix가 있는 키의 fill을 처음 시작시킨 경우에만, 첫 진행 신호 전까지 캐시 prefix 서빙을 보류"라는 게이팅이 정확한지. 특히 (a) 완결 엔트리가 게이팅에서 제외돼 영원히 대기하지 않는지, (b) 신선한 다운로드와 진행 중 fill 합류 경로가 영향받지 않는지, (c) 재개-불일치 재시작(`FillSuperseded`) 경로에서 게이팅이 풀리는지 — **교착 가능성을 최우선으로 검토**하라.
2. **§2-2 `prepareFill`/`append`의 `Task.checkCancellation()`**: 액터 격리로 "검사 통과 후 원자적 완주"가 실제로 성립하는지(함수 본문에 suspension point가 있으면 성립하지 않는다 — 직접 확인하라). 취소 예외가 던져질 때 `fills`/`fillHandles`/`fillErrors`/waiter 정리가 기존 경로대로 되는지.
3. **설계 §6 무회귀 가드 9개 불변식**이 이 2건의 로직 변경으로 깨지지 않았는지 재확인(1차 게이트에서 PASS 판정했던 것들).
4. §9-1(CHANGELOG), §9-2(주석 ID), §9-3(DocC 문단) 조치 실제 반영 확인.
5. 테스트 동기화 보강(`registeredStreamCount` 접근자 추가와 3개 테스트 대기 조건 변경)이 테스트를 약화시키지 않았는지 — 검증 대상을 우회하는 방향의 수정이 아닌지 확인하라.

## 환경

부팅된 시뮬레이터가 있다(iPhone 17 Pro, UDID `55A3A4F3-3F02-43E6-9B23-116BD15D3345`). **직접 테스트를 실행해 검증하라** — 구현자의 "8회 연속 그린" 보고를 그대로 신뢰하지 말고 최소 3회 독립 실행하라. 새 시뮬레이터 부팅·생성 금지.
